# 《返潮》墙体 24 小时技术门结果 v0.1

> 日期：2026-07-15  
> 结论：**Godot 4 + Blender 混合 2.5D 技术路线通过；当前墙体形变美术原型不通过。继续使用该引擎路线，不切 Unity，不把灰盒当正式视觉。**

## 1. 本次真正回答的问题

本原型只回答：一面墙的实时形变能否由 Blender 快速生成，经 glTF 保留 Blend Shapes，在 Godot Compatibility 渲染器中播放，并直接导出普通 Windows 程序。

它没有回答：墙体事件最终是否恐怖、照片现实背景能否无缝衔接、低配朋友电脑能否稳定运行。这三项仍属于后续美术与实机门。

## 2. 技术通过项

- Windows 10 远程生产机可稳定通过 SSH 执行 Blender、Godot 导入、截图和导出；
- Blender 4.5.11 LTS 可由脚本在数秒内生成墙体、UV、法线与四个 Shape Keys；
- Godot 4.7.1 Compatibility 正确识别 `PressNear`、`TransferPath`、`PocketFar`、`DoorSwell` 四个 Blend Shapes；
- RTX 3060 上实际运行于 OpenGL 3.3 Compatibility，而非依赖 Forward+ 特效；
- 灰盒能够在正常、按压、迁移、远端墙腔、门框受压、排空状态之间切换；
- 相机轻微横移后形变仍然存在，不是单机位贴图骗局；
- Windows 导出成功并已从导出后的 EXE 再次启动验证；
- 当前包体：EXE 109,071,360 bytes，PCK 133,664 bytes；
- 远程可执行构建位于 `G:\FanChao\prototypes\wall_transfer_throwaway\builds\FanChao_WallTransfer_Prototype.exe`。

因此，不存在足以让项目切换到 Unity URP 的引擎或资产管线障碍。

## 3. 美术不通过项

### v0.1：单凹陷与单鼓包

- 读起来像两个干净圆形气囊；
- 没有墙体结构、旧修补和门框之间的内部关系；
- 证明“会变形”，没有证明“某种东西在墙内转移”；
- 与此前被否定的圆形腹部式设计本质相同。

### v0.2：修补缝迁移与多墙腔

- 事件的空间顺序变清楚，远端不再只有一个圆球；
- 但狭窄迁移脊在整墙单网格上产生明显折面、黑缝和破面感；
- 多墙腔仍然缺少真实墙皮、砂浆、空鼓与积液之间的材料层次；
- 灰色规则网格只适合技术检查，不能承担千禧海洋馆的照片现实；
- 没有声音、手部接触、贝壳落盆和旧房间混响，恐怖因果尚不完整；
- 六张阶段图能供开发判断，不能作为公开视觉原型。

结论不是“把网格加密、鼓包磨圆”。正确修订是改变资产结构。

## 4. 对生产规范的直接修订

正式墙体不得再是一张网格同时承担全部效果。拆为：

1. **承重基墙**：保持总体平面与碰撞，只有缓慢的大尺度内陷；
2. **旧修补／墙皮层**：独立薄壳，负责抬起、空鼓、沿接缝开裂和局部脱离；
3. **内部压力层**：只在短暂迁移时出现，沿砂浆缝和旧门轮廓运动，不作为一条连续肉脉；
4. **响应物件层**：门框、柜脚、搪瓷盆和墙内松动物各自承担可听、可见的后果；
5. **排空后的空间层**：切换到具有真实深度的旧处理间，而不是让墙面简单消失。

Blend Shapes 继续用于大尺度形变；墙皮裂开与迁移路径使用独立几何、遮罩动画或骨骼，不强迫一张墙网格完成。

## 5. 下一门，而不是继续精修灰盒

下一步建立海洋馆员工走廊的正式空间骨架，先完成：

- 危机前可信的 2000 年海洋馆材料、照明与尺度；
- C03 主机位和 C04 互动近景的无缝切换；
- 双层墙体的正常态和一次不带最终贴图的动作测试；
- 柜子、门框、搪瓷盆与声音的响应链；
- 一张预渲染背景与实时墙体边缘的衔接测试。

只有当“普通走廊首先像真实存在过”后，才判断同一动作是否达到恐怖强度。

## 6. 尚未通过的项目门

- 没有照片现实人物，G3 人物／怪物生产门未通过；
- 没有预渲染背景，混合 2.5D 的接缝仍待验证；
- 没有完成海雾压力前缘和玻璃承压；
- 当前程序是可删除技术原型，不进入正式游戏代码库。
