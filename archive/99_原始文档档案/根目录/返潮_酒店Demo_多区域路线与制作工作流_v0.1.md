# 《返潮》酒店 Demo：多区域路线与制作工作流 v0.1

## 当前目标

做一段可本地运行、约 8–12 分钟的肩后实时恐怖体验。强度来自玩家在同一栋酒店里逐步失去对距离、时间、视野和出口的信任，而不是靠文字选择、怪脸闪现或单房间机关。

当前可运行主锚点：`prototypes/h00_siren_ps3/`。

## 已经改变的判断

- **保留**：前台的红电话、借视、跨重力 214 钥匙和总机改道是有效的核心规则教学。
- **修正**：前台不能承担完整 Demo，只保留为约一分钟的路线枢纽。
- **新增**：婚宴厅是第一主猎场；酒店外部负责抵达、建立整栋建筑和回收逃生后果。
- **更新**：客房短层第一版已接入正式路线；四门灰盒、镜前借视和楼梯门返回成立，M01 的完整身体连续体仍延后。
- **放弃**：H00、W01、返程墙同时常驻。三者理论解码显存超过 2GB，浏览器版采用门后分区流送。

## 当前路线

```text
雨夜停车场
  -> 装卸门
  -> W01 婚宴厅：实际绕桌到扩声台
  -> 切断主扩声：来客巡查 / 镜后返席 / 返程墙形变
  -> 穿过返程墙
  -> H00 前台：电话 / 借视 / 214 钥匙 / 总机
  -> 员工后门
  -> M01 客房短层：214 / 216 / 218 / 220 门列与镜前借视
  -> 楼梯门回到同一停车场
  -> 214 打开面包车
```

## 每区只推一条异常到极致

| 区域 | 玩家动作 | 失去的可靠性 | 可检查反馈 |
|---|---|---|---|
| 酒店外部 | 穿过无地平线的雨夜开放区 | 距离 | 酒店窗、车灯和雨声不能稳定表示远近 |
| W01 婚宴厅 | 亲手切断主扩声并利用桌阵遮挡 | 时间 | 扩声少一拍，席面、镜子和 CRT 仍按不同时间继续 |
| H00 前台 | 借视后把 214 从两套重力中抽出 | 视野 | 只有来客视野能补全钥匙与总机的关系 |
| 客房层（第一版已接入） | 在四扇房门间读取同一身体 | 尺度 | 直接视野看局部，镜前借视打开楼梯门；完整身体连续体仍待制作 |

## 生产工作流

1. 每次只扩一条真实可走路线，不先做远景百科。
2. 先为不可跳关的状态写失败测试，再实现交互。
3. 资产先按显存与 draw call 判断是否能常驻；过门时保存唯一会话状态并卸载旧页。
4. 每一区先通过第一帧构图，再验证真实键盘移动、碰撞、交互和返回路线。
5. 浏览器截图只算画面证据；完整状态、控制台零错误和实际输入回放同时成立才算该段通过。
