# 《返潮》莫比乌斯小镇：F0 连续路线体验复审 v0.2

> 结论：**完整路线的内部视觉复审从“失败”提升为“候选可读”。** 当前版本能在真实连续行走中依次显示方位迟滞、双海岸、镇面卷起和同地另一面；物理岸线条带已把 V3 场景工作量压到远低于 33.3ms，但当前内嵌浏览器连空场景都无法稳定满足 RAF 门，因而 720p 30fps 仍只能记为“待独立宿主复核”。外部无标题盲读也没有完成，所以第 3 层仍未冻结，也不迁移 Unreal。

## 1. 这次真正改变了什么

旧版本把卷曲绑定到固定世界 X 轴，只有 F0 明信片机位能读懂；路线一转弯，异常就留在玩家身后。v0.2 改为一条沿 270m 路线参数化的连续镇面带：

- 路线弧长是纵轴，左右岸和镇面宽度是横轴；
- 玩家周围 30m 由移动近景遮罩保持水平；
- 前方约 30—100m 的正侧镇面围绕道路切线翻起；
- 干燥主路、支路、屋顶带、海堤带、海面、电杆和电线使用同一条 `routeFoldSample`；
- 同一张连续海面改为沿真实岸线生成的左右物理条带，在 V2 路段形成左侧内湾与右侧外海；两岸通过镇面下方的深水接缝保持同一拓扑对象，不再用覆盖整镇的透明矩形与片元丢弃伪造岸线；
- 没有自动转头、镜头吸附、屏幕空间扭曲或分阶段换景。

这使“莫比乌斯”从固定构图技巧变成了可沿路线观察的世界结构。

## 3. 五段当前判定

### V1 / 67.5m：候选可读

道路继续可信前进，屋顶群与广播塔—烟囱—蓝穹顶仍是同一组对象，但天际线相对道路弯向表现出迟到。它不是相机旋转造成的换位。

### V2 / 135m：候选可读

路线成为一条干燥岛脊。连续海面沿左侧内湾靠近道路，同时在右侧展开外海；两次海岸被镇面和岸缘分开，不再是空地平线，也不是两块重复水面。

### V3 / 202.5m：候选可读，宿主帧率待复核

正侧镇面进入天空，但不再是一整块黑幕：支路、屋顶、海堤和海面保持不同颜色与间隙，共享一个卷曲中心。最近 30m 的主路保持水平。物理岸线版本在 1280×720 下为 `29 calls / 16,276 triangles`；更新加渲染的工作时间 `p95=1.4ms`，不是当前 RAF 峰值的来源。

### V4 / 270m：候选可读

黄线、市场铺面、修理棚和公交镜仍在原处；卷曲已消失，三地标顺序与海岸归属翻转。末段新增建筑和电杆已经退出 F0 的 30m 固定区。

## 4. 还不能说完成的两件事

1. **无标题盲读未做。** 至少 6 名未读设定者必须只看实际连续路线，能复述“海从两边出现”“镇面翻过头顶”“回来后海和地标换边”中的两项以上。
2. **30fps p95 仍未被合适宿主证明。** 同一内嵌浏览器、同一 10 秒窗口中，空场景（`0 calls / 0 triangles`）的原始 RAF 已是 `p95=33.7ms`、仅 `79.59%` 帧低于 33.3ms；完整 V3 为 `p95=34.2ms`、`70.03%`，但其实际场景工作 `p95=1.4ms`。因此不能把宿主调度峰值误判成海面瓶颈，也不能据此宣布实机 30fps 通过。下一次性能判定必须换到可控制前台状态的独立 Chrome/GPU 环境。

## 5. 下一步

保持现有空间结构不扩玩法。帧时间记录器现在同时记录两组数据：原始 RAF 间隔用于最终实机门，更新加渲染的 `work` 用于区分内容负载与宿主调度。自动审查还提供 `profile=scene_off` 空场基线；这些参数不能用于视觉通过，只用于诊断。

下一轮停止删减世界换帧率。先把当前五段空间命题翻译为 F0 的 PS3 末期美术状态板，并输出可给 6 人直接观看的无标题连续录像或可执行链接；并行在独立前台 Chrome/GPU 环境复核整圈 RAF。盲读与独立宿主性能都通过后，才迁移 Unreal；美术原型本身不再被当前内嵌浏览器的空场帧率锁死。
