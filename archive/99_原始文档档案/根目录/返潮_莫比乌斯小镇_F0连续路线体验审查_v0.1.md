# 《返潮》莫比乌斯小镇：F0 连续路线体验审查 v0.1

> 审查结论：**路线状态闭合通过，连续视野证明未通过。** 当前样片可以在没有门、黑场和传送的情况下走完 270m 并翻转 `route_parity`，但中段没有让玩家看见与状态同强度的全镇异常。它仍是技术灰盒，不能作为美术候选，也不能触发 Unreal 迁移。

## 1. 实测方式

- 日期：2026-07-20；
- 浏览器视口：1280×720；
- 地址：`/prototypes/f0_mobius_walk/?automation=1&walk=1`；
- 审查通道只持续模拟按住 W，不调用 `setProgressForAutomation`，仍由真实动画帧、2.25m/s 步速、同一条 Catmull-Rom 路线和同一个 `advanceRoute` 推进；
- 全程 URL 未切换，终点没有门、黑场或传送。

首轮自动行走暴露了负首帧时间差：自动前进会把负距离交给 `advanceRoute`，渲染循环因此正确报错停止。现已把帧时间夹在 `0—0.05s`，修正后没有新增控制台错误。

## 3. 为什么判失败

1. **状态名先于画面成立。** HUD 写着“双海岸”，画面却没有同时可读的两段海、干燥近路和被夹在中间的镇面。
2. **F0 明信片与路线脱节。** 固定机位能看见三地标换位；路线一转弯，这组世界体块就在玩家身后，中段没有自己的视野论证。
3. **卷起没有贯穿构图。** Phase 0.75 的道路、屋顶、海堤和电线虽调用同一函数，但当前路线视角没有把这些对象同时放进画面，因此代码共曲率不等于玩家看见共曲率。
4. **终点过强，中途过空。** 玩家只在最后一帧重新获得清楚构图，会把体验读成“走一圈后换景”，而不是翻面一直在发生。
5. **灰盒没有路线戏剧。** 当前楼群按世界网格散布，路线只是在其中穿行；它没有安排何时露出地平线、何时让道路压住海、何时让屋顶跨过天空。

## 4. 下一版不是加装饰，而是重排五段视野

唯一允许的修正方向是 `world_data/retide_f0_route_vistas_v0.1.json`：让路线的每一段都拥有可见的空间命题，并由真实世界网格承载。

- 不用镜头强吸附、自动转头或后处理提醒玩家看哪里；道路切线、坡度和遮挡本身应把视线送到证据上；
- 不复制五套舞台；同一海面、镇面、道路和三地标应在连续世界中从不同切口被看见；
- 不把 HUD 状态名当证据。下一轮审查截图必须隐藏 HUD，仅凭画面判断阶段；
- 每个关键距离同时保留一块不弯的 0—30m 路面，以及至少两类发生共同拓扑变化的中远景对象；
- 只有 0m、67.5m、135m、202.5m、270m 五个**实际行走采样点**都能读出对应命题，路线体验才可重判。

## 5. 当前允许继续的工作

先重构路线视野载体：单一海岸网格的双重可见弧、沿路线切线布置的屋顶/电线轮廓、Phase 0.75 可跨越天空的连续镇面，以及 F0 不变近景的回程接缝。暂不制作第 4 层材质、天气、角色、敌人或叙事内容。
