## Gemini 结论摘要

Gemini 给出三个候选：

- A 婚宴后场：现实可读性 5、路线清晰度 4、异常证明度 5、人物关联度 5、资产复用度 4，总分 23/25。
- B 食堂侧间：现实可读性 5、路线清晰度 4、异常证明度 4、人物关联度 3、资产复用度 5，总分 21/25。
- C 海洋馆服务走廊：现实可读性 3、路线清晰度 4、异常证明度 3、人物关联度 2、资产复用度 3，总分 15/25。

推荐 A，理由是婚宴后场同时提供千禧媒介、公共礼数、缺席和身份关系；海洋馆容易被误读为漏水或传统海怪题材。

## Gemini 提出的关键因果

### A 婚宴后场

```text
宴会厅入口
    │
后场服务走廊 ─── 录像/广播控制室 ─── 卸货口
    │                                  │
    └──────────── 洗涤间 ──────────────┘
```

NPC 旧工作路线是“卸货口 → 服务走廊 → 录像/广播室 → 洗涤间 → 卸货口”。异常通过低处受压、密封件变化和声学阻尼共同证明。实体必须出现在旧工作路线，而不是随机刷怪点。

### B 食堂侧间

```text
打饭窗口
    │
出餐后台 ─── 铁皮柜/账目角 ─── 洗碗槽
    │                              │
    └──────────── 备料库 ───────────┘
```

现实和资产复用很好，但人物关系与千禧媒介证据较弱，且空间容易太直白，路线选择不足。

### C 海洋馆服务走廊

```text
参观区过渡门 ─── 干式维保走廊 ─── 泵机房
       └──── 高位天桥 ─── 滤缸室 ──┘
```

它适合后续证明“正常海水容器与外部干燥深压并存”，但首个 Demo 容易被理解成水管事故或水族馆海怪。

## Codex 复核与修正

Gemini 的结构判断通过；但它提出的“广播开启就吸引实体”“关闭电门就改变巡查”目前缺少世界内因果，先不纳入 Round 1。第一版只保留一个核心选择：玩家依据声音与材料证据选择公共路线或后场低处路线。

另外，图中的“不可见水深分界线”仅是设计标注，不能出现在实际游戏画面中；不能把它实现成可见发光线、颜色滤镜或装饰腰线。

当前决策：**A 进入 Round 2，B 作为备用，C 延后为第二场景。**
