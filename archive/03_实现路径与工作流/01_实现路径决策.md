# 可能的实现路径与当前选择

## 路径 A：H00 独立 Unreal 5.8（当前主线）

`FanchaoH00UE` 是轻量独立工程，当前用 C++ 运行时生成灰盒空间、玩家占位体、录像台、实体航点和重置逻辑。它的目标是先验证 H00 的可玩行为，不复制约 2.8 GB 的旧泥滩工程，也不把正式模型提前塞进来。

下一步顺序：

1. 复验空 `Entry` 地图的玩家镜头、照明和可见画面。
2. 人工跑完 60--90 秒路线，记录让行、机位和录像归档手感。
3. 用 2001 年真实道具替换占位体，保留异常因果和声音 Gate。
4. 再让 Gemini/Antigravity 生成候选形体，由网页 Chat 端做视觉逻辑审计。
5. Hunyuan3D 只在形体 Gate 通过后用于可修改候选网格；ComfyUI 只在需要本地可重复贴图/参考图时启用。

## 路径 B：Mudflat_Runtime 技术证据（历史/备选）

旧路线的 `FanchaoMudflatUE` 已有独立非 World Partition 运行地图、控制箱、塔内电话、`E/E/R` 交互和自动警报日志；它证明了 UE 5.8 工程、输入、日志和资产接入可以稳定运行。

它不再作为当前 H00 的创作地图。只提取可复用的工程经验、输入、重置、日志和打包脚本，保留原工程与验证记录以便回溯。

## 路径 C：食堂/海洋馆/小镇旧切片（候选/后置）

食堂仍适合作为普通劳动、声音和年代底片的备用切片；海洋馆用于展示“缸内真实海水 vs 缸外干燥空间承受深度”的强对照，但均后置到 H00 行为和美术 Gate 之后。

## 不采用的路径

不再先生成一张怪物图，再反向发明空间、动作和地图；不把 Hunyuan3D/ComfyUI 安装本身当成进度；不把 Agent 的视觉审查文本当作 PNG 视觉通过证据。
