# CRT 阈限录像系统 —— 录像先于现实

> 本作核心机制之一。继承旧稿《古海外壳与电视预现原型 v0.1》第 6–7 节已验证规则，
> 在其上补齐：屏幕分布、观看/对照/被迫面对的玩法化、映射规则表、破像系统、技术实现。

---

## 1. 一句话定义

**酒店与海洋馆里的每一块 CRT 屏幕，显示的都是"当前空间正被返潮推向的下一稳定形态"。**

不是未来十秒的录像回放，不是预知梦，而是：显像管玻璃、荧光粉、磁带比建筑材料更早承受返潮，所以屏幕先一步到达。

## 3. 预现规则（能显示 / 不能保证）

### 3.1 屏幕能提前显示

- 尚未从建筑中脱离的外板、尚未收拢的墙面、尚未获得深度的旧门框；
- 现实中不可见的东西：上宾缺失软体的灰黑轮廓、全福婆的现实位置（仅镜面）；
- 实体下一议程将占据的门、走廊、房间；
- "未来的玩家"：若保持当前行动，玩家将被包围/引座的位置；
- 危机前人物留下的动作（婚宴宾客、摄像师），被即将到来的结构遮挡。

### 3.2 屏幕不能保证

- 精确发生时间（只保证"下一议程内"）；
- 玩家一定站在画面中的位置（玩家可以让画面失效——见破像）；
- 所有细节按录像重复；
- 关闭电视能取消事件（关屏只是放弃情报）。

### 3.3 同步律（核心演出规则）

- 现实越接近预现态，屏幕与现实的**同步偏差越小**（画面延迟、声音提前量都收窄）；
- 完全重合的一瞬间：画面异常清晰 1–2 秒 → 失去信号 → 该屏幕此后只显示雪花——**"这个空间完成了"**；
- 声音先于画面先于现实：玩家会先从 CRT 喇叭里听见栏杆被磨弯的声音，数秒后现实栏杆才开始弯。

## 4. 玩家如何观看 / 对照 / 被迫面对

### 4.1 观看（侦察动词）

- 走近屏幕自动聚焦（轻微推镜 + 现实环境声衰减），无需按键切换模式；
- 观看没有次数与时长限制，但**观看时玩家在现实中是背对房间的**——所有屏幕的摆放都刻意让玩家背对最大的入口。观看行为本身有代价，这是"阈限"的玩法含义。

### 4.2 对照（解谜动词）

差异点 = 情报。Demo 中使用的差异类型固定为四种（不再扩充）：

| 差异类型 | 例 | 告诉玩家什么 |
|----------|----|--------------| 
| 多出之物 | 录像里服务走廊尽头多一扇敞开的门 | 下一议程会出现的通路 |
| 缺失之物 | 录像里主桌少了"上宾"席 | 上宾已离席=正在大堂 |
| 错位之人 | 回眸客在录像里站在楼梯口，现实中在窗边 | 她现实位置与录像位置的连线指向可用物/路 |
| 未来的自己 | 画面角落有个穿伴娘裙的背影 | 警告：按当前路线走会到达那里 |

### 4.3 被迫面对（恐怖动词）

- 关键必经路线的预现里**总有一样东西在等玩家**；看过之后，玩家走这条路的每一步都在与记忆里的画面对照——设计上要保证"画面兑现时与录像有一处不同"（更近、更慢、或已转向玩家），预告不消解恐怖，反而加深。
- 依赖屏幕的惩罚（继承旧稿）：Demo 后期，T04 九宫格中会有一格显示**摄像机背后的空间**——"谁在看"成为新的威胁。仅演出，不做实体。

## 5. 破像系统（玩家的有限反抗）

### 5.1 规则

- 每个关键空间存在 1 个**锚点物**：预现画面构图中足够醒目的可交互物（录像里完好的大花瓶、录像里没有的一把椅子、录像里亮着的一盏灯）。
- 玩家对锚点物执行破像动作（打碎/搬入画面/关灯），使现实与录像出现**不可调和的构图差异** → 该空间的本次预现作废，空间维持当前态一个议程周期。
- 破像有声：动作本身产生大噪声，必触发一次司仪点名。**用安全换时间**，不是免费暂停。
- Demo 配额：自由破像 3 次 + 终局强制大破像 1 次（见 `10` 文档）。

### 5.2 破像的叙事含义

录像是海写好的席位安排；破像是把自己的名字从席位牌上划掉一次。司仪广播会在破像后"更正议程"（重新宣布同一议程，措辞更冷），全场浮客短暂转头面向玩家方向——代价看得见。

## 6. 屏幕↔现实映射规则（给关卡与程序的硬约束）

1. **一屏一空间**：每块屏幕只预现它物理所在（或监控机位对准）的空间，不做全知电视。
2. **构图锚定**：预现画面的机位=该屏幕对应的固定虚拟相机位；玩家在现实中站到同机位可逐元素对照。
3. **状态对应**：预现态=该空间在`当前议程+1`的状态资产，不做逐秒时间轴。
4. **实体入画规则**：实体在预现画面中以"下一阶段行为"出现（司仪已上台、侍应已到走廊尽头），位置取自实体状态机的下一节点，不做 AI 预演算。
5. **失效规则**：空间完成态切换后，对应屏幕永久雪花；破像后屏幕黑屏至下一议程。
6. **镜面特例**：T06 梳妆镜遵守全部屏幕规则，但左右镜像、无扫描线、无声——它是"最干净的屏"，也因此最可信、最恐怖。

## 7. 技术实现（Three.js）

| 模块 | 方案 | 成本 |
|------|------|------|
| 预现画面 | 第二相机渲染"下一态"场景层到 512×384 RenderTarget，贴 CRT 屏幕材质 | 每帧一次低分辨率 pass，可隔帧渲染 |
| 固定演出画面 | 预渲染视频纹理（VideoTexture），如 T03 婚礼 VCR、T05 母带 | 离线制作，运行时零逻辑 |
| CRT 质感 | 屏幕材质 shader：隔行扫描、拖影（前帧混合）、偏色、桶形畸变、行频噪点 | 单 shader，全屏幕共用 |
| 同步律 | `syncGap` 参数（由议程状态机输出）驱动声音提前量与画面延迟 | 播放调度，无渲染成本 |
| 破像 | 锚点物交互 → 置 `foretold=false` → 屏幕切黑屏材质 + 状态机挂起一档 | 纯状态逻辑 |
| 镜面 T06 | 平面反射（Reflector）渲染"下一态"层而非当前层 | 与 RenderTarget 同源 |

**关键结论：整个系统不需要任何"时间"技术，只需要每个空间多一套状态资产 + 一台第二相机 + 一张状态表。这就是它必须成为核心机制的理由——恐怖效果与实现成本的比值全项目最高。**

## 8. 视觉与声音规范

- 画质：低分辨率、隔行、拖影、偏色、弱动态范围；未来结构首先表现为**压弯扫描线的暗弧与高亮矿物边缘**；
- 禁止：数字 glitch、彩色像素块、datamosh、现代录屏噪点、漂浮全息 UI；
- 声音：行频啸叫的不可能滑音；预现声提前量随同步律收窄；失去信号后房间残留一段来自显像管内部的湿摩擦声。
