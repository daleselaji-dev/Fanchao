# 《返潮》技术栈与制作工作流

> 状态：现行宪法。回答：用什么做、怎么做、怎么算做完了。
> 2026-08-24 修订：引擎裁决从单栈（UE 5.8）改为**双栈**。修订依据：① Demo 的下一执行者很可能是 Cursor Cloud Agent，该环境**无法运行 Unreal Editor**——单栈裁决会让 Demo 永远卡在没人能执行的状态；② PR #3 已证明浏览器灰盒在云端环境可运行、可截图、可回归（`demo/web/` 工程事实）；③ 用户点名要求对「虚幻 vs Three.js」给出诚实结论，不许「都可以」。

## 1. 技术栈裁决（双栈）

### 1.1 裁决（无模糊空间）

| 栈 | 技术 | 承担什么 | 谁执行 |
| --- | --- | --- | --- |
| **Demo 执行栈** | **Three.js（WebGL）+ 原生 ES Modules，浏览器运行** | 可玩 Demo、空间灰盒、M01 行为合同、镜头语法验证、轮廓双读验证、程序化声音、自动截图 | Cloud Agent 或任何有浏览器的人，按 [docs/agent-playbook/](../agent-playbook/README.md) 执行 |
| **正式产品栈** | **Unreal Engine 5.8**（沿 `demo/ue/H00_Source` 工程） | PS3 级最终画质、烘焙光照、照片投射资产管线、垂直切片成品与正式产品 | 只指派给装有 UE 5.8 的本地开发机（人类），**云端 Agent 永远不领 UE 任务** |

一句话分工：**一切「现在就要能跑起来给人看」的东西归 Three.js；一切「最终画质与成品」的东西归 UE 5.8。** 不存在第三条路线，不并行维护第二产品引擎。

### 1.2 论证：虚幻 vs Three.js，各自赢在哪

**Three.js 赢在「Agent 能真正跑起来」**——这是 Demo 阶段的决定性标准：

- 云端执行环境无 GPU 编辑器授权、无法安装运行 Unreal Editor；指派 UE 任务给 Cloud Agent 的结果是 100% 空转。这不是偏好问题，是执行环境事实；
- 浏览器栈在本仓库已有直接证据：`demo/web/`（Canvas 2D）在云端环境完成开发、运行、9 张截图与行为回归——同一环境跑 Three.js（WebGL）没有额外风险；
- Demo 需要验证的全部合同（空间拓扑、行为状态机、固定机位构图、轮廓双读、声音先于画面）都在 Three.js 表达能力之内；headless Chromium 可自动化截图与录像，验证闭环不依赖人肉；
- 交接包的 Three.js 前科（`h00_siren_ps3` 11 项状态测试全过、`f0_mobius_walk` 连续翻面走通）证明这条栈承载行为与空间验证绰绰有余。

**UE 5.8 赢在最终画质与产品管线**——这是产品阶段的决定性标准：

- PS3 级照片写实（烘焙 GI、材质保真、后期管线）是 UE 开箱能力；Three.js 要达到同等画质需自建烘焙/资产/灯光全套工具链，对单人+AI 产能不现实；
- `FanchaoH00UE` 与 `Mudflat_Runtime` 已消化过一轮引擎风险（可编译、状态机、航点、归档、复位、GLB 导入均有历史日志）；
- 死魂曲式灯光导演、照片投射贴图低模人物在 UE 有成熟工作流。

**处理旧条款**：

- 旧版本文档 §1.3「Three.js 原型永久停止新开发」**废止**——该条写于「单栈 + 本地开发机」假设下；新裁决限定 Three.js 只承担 Demo 执行栈，不承担产品，不构成并行产品引擎；
- 交接包 Godot 混合 2.5D 复判维持归档不执行；其预算纪律继续全部继承：不依赖 Lumen/Nanite/硬件光追、固定/受限机位保证构图证据（[02 §4](02_视觉原型设定.md#4-镜头语法)）、拿最差目标机器当下限、引擎不替创意背锅。

### 1.3 UE 迁移时机与前置合同

UE 迁移**只在垂直切片（P1）立项时发生**。迁移前，以下合同必须已在 Demo 执行栈拿到可复核证据（截图/录像/测试日志），未经 Demo 栈验证的设计不得在 UE 里首次实现：

1. M01 行为合同基础层与扩展层（[03 §3.1](03_核心玩法.md#31-m01-返席人无正面的父亲行为合同)）——状态机、航点、让行、沿声改向；
2. 空间拓扑与尺寸表——A—E 后场闭环 + 海洋馆服务走廊，门位、路线长度、视线遮挡关系锁定；
3. 三个关键镜头的固定机位构图（散场宴会厅 / 门框切肩线 / 侧向证据）；
4. 声音先于画面的触发表（哪个位置、先听到什么、几秒后看到什么）；
5. M01 轮廓双读在 720p 灰盒下成立（背影读成人、侧面读出主异常）；
6. 测深回声两族听感（清晰短促 vs 拖长降调）的节奏原型（程序化合成即可）。

UE 线自己的第一任务维持不变：`Entry` 地图黑屏复验、非黑屏 720p 截图 ≥3 张——但它是本地开发机任务，**不阻塞 Demo 执行栈的任何一步**。

### 1.4 后备与边界

- 若 UE 5.8 在垂直切片阶段出现不可绕过的管线阻断（非创意问题），降级评估点是 P1 气质门，届时凭证据重开裁决，禁止拍脑袋切换；
- Demo 执行栈禁止追求最终画质：不引入 PBR 材质库、不做烘焙光照仿真、不给灰盒贴照片纹理。Demo 栈的画面上限是「构图与轮廓正确的灰盒 + 少量纯色材质分区」，把画质留给 UE，防止两栈互相蚕食；
- `demo/web/`（Canvas 2D 行为灰盒）冻结维护：只修 bug 不加功能，作为行为合同的回归基线保留。

## 2. 资产管线

### 2.1 流水线

```
参考照片采集（实景/器物/人物）
   → Blender（灰盒 → 精模 → UV/烘焙 → glTF/FBX 导出）
   → Photoshop / ComfyUI（照片投射贴图、PBR 材质，本地可重复）
   → UE 5.8（导入、材质实例、烘焙光照、LOD）
   → 720p 轮廓复核 → 资产门验收
```

- 上述照片管线**只服务正式产品栈（UE）**。Demo 执行栈的资产通道独立且极简：程序化几何 + 低模 glTF + 纯色材质分区，禁止照片纹理（清单与占位策略见 [docs/agent-playbook/](../agent-playbook/README.md)）；
- **照片采集是第一资产来源**（SIREN 方法）：千禧器物（CRT、搪瓷杯、控制箱、红绒椅套）优先实物拍摄/扫描；人物脸手用真人照片投射贴图低模；
- 命名沿用交接包已建立的代号体系并制度化：场景 `W__`（W01 婚宴厅）、切片 `H__-R_`（H00-R0）、威胁 `M__`（M01）、玩家 `P__`、NPC `N__`、家庭 `F__`、莫比乌斯路线 `R_`、原型 `F_`（F0）。

### 2.2 AI 工具的位置（Gate 化，防止工具即进度）

| 工具 | 允许用途 | 禁止 |
| --- | --- | --- |
| 网页 Chat（GPT 等） | 视觉逻辑审计、文档评审 | **审查文本不算视觉证据**——只认 PNG/截图/录像 |
| Gemini / Antigravity CLI | Blender 脚本、低模生成、技术检查 | 直接产出正式资产 |
| Hunyuan3D | 图生 3D 候选网格 | **只在形体 Gate 通过后**启用；产出一律入 `CANDIDATE` |
| ComfyUI | 本地可重复的贴图/参考图 | 生成图反向修改设定（病史条款） |
| 图像生成（Midjourney 等） | 情绪板、参考 | 直接转资产；代替 [02 §6](02_视觉原型设定.md#6-原型制作门) 的实机基准图 |

### 2.3 已有资产处置

W01 婚宴厅 GLB、海洋馆走廊 GLB：导入 UE 后按 [02](02_视觉原型设定.md) 重审材质再上岗；M01 各版本候选 GLB 维持 `CANDIDATE`，不算正式资产。

## 3. 声音管线（第一叙事层）

- **验收顺序宪法**：每个异常事件永远按「声音成立 → 动作成立 → 画面成立」的顺序制作与验收，倒序即退回；
- 采集优先：千禧设备实录（继电器咔嗒、扩音器啸叫、CRT 高频、餐具、卷帘、拨号音）建立现实底层声音库——现实声音不够具体，错位后就只是通用恐怖音效；
- 测深回声是**系统性声音设计**：清晰/拖长两族回声 + 方向差编码，在 UE 音频框架（MetaSounds + 空间化/遮挡）内做成参数化系统，不做一次性音效；
- 三种错位（地点/时间/身份）每段声音只用一种；禁止清单沿用交接包：不用突然巨响替代事件、不用倒放人声与儿童笑声当默认诡异、静默必须有来源。

## 4. Gate 制度与制作循环

### 4.1 原则

- **每轮只交付一个通过 Gate 的产物**。多个半成品=零进度；
- **证据文化**：「已完成」只认三种证据——可运行、有截图/录像、有日志。文档写完不算完成任何事；
- 阶段门定义见 [00 总览 §2](00_项目总览与规划.md#2-阶段规划)：P1 内部五门（机制→气质→威胁→资产→成片）失败退回，不得用堆资产补救。

### 4.2 单轮制作循环

```
领取当轮唯一目标（对应某个 Gate）
 → 灰盒/原型实现 → 自测并留日志
 → 录屏/截图 → 外部盲测（若该门要求）
 → 通过：合入主线并打 tag；不通过：写明失败原因，退回或换法
```

### 4.3 测试制度

- 行为逻辑（状态机、认领进度、声路由）写成可重复的自动化测试：Demo 执行栈用**状态纯函数 + Node 断言脚本**（继承 `h00_siren_ps3` 的 11 项测试方法论），迁移 UE 后以 Automation Test 复刻同一套用例；
- Demo 执行栈的视觉验证用 headless Chromium 自动截图（`tools/capture_screenshots.py` 的方法论），关键状态可用 URL 参数确定性复现；
- 每个视觉验收都附 720p 复核（轮廓双读、证据可读性）；
- 外部盲测的标准问题固定化：「这里哪里不对？」「它是什么？」「你为什么走这条路？」——能复述设计意图即通过。

## 5. 版本控制与目录制度

### 5.1 Git 制度（原工作目录长期无版本控制，此为最高优先级补课）

- 本仓库为唯一真相源。UE 工程入库，二进制资产（`.uasset`、GLB、PNG、WAV）走 **Git LFS**；
- 分支：`main` 保护；每轮 Gate 工作开 `work/<gate名>` 分支，通过后合入并打 tag（如 `P0-视觉QA复验`、`P1-机制门`）；
- 提交信息前缀：`docs:` / `proto:` / `asset:` / `audio:` / `fix:`；每个逻辑变更一个提交；
- **设定文档修订直接改本目录文件，用 git 历史追溯**。禁止另开「v0.x 评审稿」平行文件——那正是交接包烂掉的方式。

### 5.2 目录与状态标签

```
/docs/game-design/       现行宪法（本目录）
/docs/agent-playbook/    下一 Agent 的逐步执行文档（Demo 生成手册）
/docs/notes/             阅读笔记、盲测记录、Gate 失败归档
/demo/web/               H00-R0 Canvas 2D 行为灰盒（行为合同回归基线，冻结维护）
/demo/web3d/             Three.js 3D Demo（Demo 执行栈主工程，按 playbook 产出，当前尚未创建）
/demo/ue/H00_Source/     UE 5.8 参考源码（正式产品栈起点，本地开发机任务）
/assets/maps|storyboard|screenshots|concept|graybox-renders/   审阅与验证资产
/assets/candidate/       CANDIDATE：候选资产（AI 产出一律先进这里）
/assets/canon/           CANON：通过资产门的正式资产
/tools/                  截图与图表生成脚本
```

交接包 zip 仍在仓库根目录，为唯一历史层；**不再把 zip 整包解压入库**（需要查原文时临时解压到仓库外，方法见 [docs/game-design/README.md](README.md)）。

任何文件只有三种身份：`CANON`（现行有效）、`CANDIDATE`（排队待审）、`ARCHIVE`（冻结，禁止引用为依据）。身份变更必须经 Gate 或 [05 审定文档](05_设定审定_保留与删除.md) 裁决。

## 6. 性能与资产预算（PS3 级的工程口径）

与 [02 §5](02_视觉原型设定.md#5-ps3-级画质的可量化定义) 的美术口径对应：

| 项 | 预算 | 说明 |
| --- | --- | --- |
| 分辨率/帧率 | 1080p/30fps 稳定；720p 兜底 | 在指定低配验收机上测，不用开发机自证 |
| 场景三角形 | 单场景 ≤150 万（含所有 LOD0 同屏） | 婚宴厅闭环为基准场景 |
| 英雄资产 | 单件 ≤5 万三角形，2K 贴图 | 控制箱/推车餐具/门框卷帘/人物脸手 |
| 量产资产 | 单件 ≤8 千三角形，1K 贴图，模块化复用 | 桌椅、管线、货架 |
| 角色 | ≤4 万三角形，照片投射贴图 | M01 与 P01 允许上浮 50% |
| 动态光 | 每场景 ≤4 盏 | 其余全烘焙；应急灯/CRT/扩音器灯优先占名额 |
| 半透明 | 玻璃与雾片总覆盖 ≤15% 屏幕 | 海洋馆玻璃场景单独立预算 |
| 包体 | 垂直切片 ≤3 GB | 含音频 |

预算超支的处理顺序：先砍面数与贴图分辨率，再砍动态光，**永远不砍声音**。

## 7. 工作流不做清单

- 不做日历排期（只做通过门）；不同时推进两个 Gate；
- 不在形体 Gate 前生成怪物模型；不在五图基准门前量产资产；
- 不把工具安装、文档撰写、AI 生成计为进度；
- 不维护并行引擎版本；不为「以后可能需要」预制系统；
- 不允许任何成员（包括 AI 代理）以「探索稿」名义绕过本目录直接新增设定文档。
