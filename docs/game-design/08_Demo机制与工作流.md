# 《返潮》Demo 机制与工作流

> 状态：现行执行文档，取代 `docs/agent-playbook/README.md`（旧手册的工程方法保留，其怪物命名、形象与恐怖表现已随 M01—M04 废案作废，以 [07](07_恐怖核心与怪物设计.md) 为准）。
> 读者：执行 Demo 的 Agent 或任何有浏览器的人。

## 0. 一句话任务

在 `demo/web3d/` 用 Three.js 做出 H00 婚宴后场的 **60–90 秒可重复、可玩 3D 灰盒**：五区闭环 + W00 看见时刻 + M05 双背 + 程序化声音 + 自动测试 + 可复现截图。

## 1. 执行栈（锁定，无模糊空间)

- **Demo 执行栈 = Three.js（浏览器）**。正式产品栈仍为 UE 5.8（[06 §1](06_技术栈与制作工作流.md#1-技术栈裁决双栈)），Demo 阶段不碰 UE。
- **断网可玩**：three 用 npm 装最新稳定版后把 `node_modules/three/build/three.module.min.js` 拷入 `demo/web3d/vendor/`；运行时零 CDN、零打包器、零框架、零 TypeScript。
- 运行：`python3 -m http.server 8000` → `http://localhost:8000/demo/web3d/`。
- npm 只用于取 three 与开发期工具（测试用 Node 自带 `node --test`，截图用 headless Chromium）；`node_modules/` 不入库。

## 2. 工作流（四步，每步有退路，禁止停工）

| 步 | 产出 | 通过线 | 失败退路 |
| --- | --- | --- | --- |
| ① 视觉原型 | 场景灰盒 + W00 元素 + 固定机位截图 | 广角一帧读出「散场、无人、不对劲」 | 若尝试 image-to-3D / Hunyuan3D 类外部管线不可用或产物不可控，**立即**退回 Three.js 程序化几何，不停工、不等待 |
| ② 玩法灰盒 | 玩家控制器 + M05 状态机（纯函数）+ `node --test` 全绿 | 行为合同逐条可测 | 状态机先写纯函数、测试先行；接不进渲染也先保测试绿 |
| ③ 地图机制 | 任务回路（持带→归档→返回）+ 程序化声音 + 低处声学 | 人工走完 60–90 秒回路 | 砍支线保主回路 |
| ④ 可玩 Demo | 截图 ≥8 张 + 审阅文档 + 诚实状态表 | §8 完成定义逐项打勾 | 未过项如实写 NOT RUN，不写「基本完成」 |

外部管线纪律：允许依赖现成项目（image-to-3D、程序化几何库等），但任何管线**一次跑不通即弃用当轮**，退回程序化占位。管线是加速器，不是里程碑；「装好了工具」不算进度。

## 3. 空间与数值（继承 2D 灰盒 `demo/web/`，禁改）

- 拓扑：A 宴会厅 / B 服务走廊 / C 录像·广播室 / E 洗涤·器材间 / D 卸货口，墙体、门位、家具与 `demo/web/main.js` 常量一致。
- 行为数值：玩家速度 **3.6 m/s**，实体速度 **1.5 m/s**，归档半径 **2.4 m**，让行触发 **<1.2 m**（前向锥）、解除 **>1.5 m**，实体路线 = 15 航点旧后勤路线 D→B→C门外→E→D。
- 坐标：2D 的 (x, y)（米，y 向下）映射为 3D 的 (x, z)，高度为 y 轴。墙高 2.8，门洞高 2.1，玩家眼高 1.6。
- `demo/web/` 冻结：只作回归基线，一个字节都不改。

## 4. 玩家与操作

PointerLock 鼠标转向 + WASD（3.6 m/s）；肩后第三人称相机（距 2.4 m、高 1.7 m，射线撞墙拉近）；`E` 交互、`R` 复位、`V` 调试标注层（房间名/航点/低处范围，**默认关**）、`M` 静音。无跳跃、无冲刺、无体力条、无小地图、无 HUD 数值。

## 5. M05 行为合同（测试即验收）

状态机只有三态 WORK / MOVE / WAIT，写成纯函数 `stepEntity(entity, player, dt)`（不 import three，可被测试与主循环共用）。合同逐条对应 `node --test` 用例：

1. 航点顺序推进，不跳点；
2. 速度恒 1.5 m/s，任何玩家行为不改变它；
3. 工作点按 pause 时长停留；
4. 让行触发：玩家距离 <1.2 m 且在前进方向锥内 → WAIT；
5. 让行解除：玩家离开 >1.5 m → 恢复 MOVE；
6. **朝向只由路线决定，与玩家位置无关**（从不无故面向玩家；他也没有可面向的那一面）；
7. **折返段不转身**：标记 `reverse` 的航点段，朝向保持不变、位移反向（倒着走）；
8. WAIT 完全静止：步态相位冻结，无余摆；
9. 归档半径 2.4 m 判定；
10. `R` 复位全量还原（玩家、实体、任务、日志原因）；
11. 整圈用时落在 60—120 s。

旧「侧向证据 1.6 秒复眼」机制随 M01 废案删除，不迁移。M05 的「看见时刻」不设脚本：玩家自己绕面即触发（形象几何保证正面=第二个背）。

## 6. 声音（程序化 WebAudio，零采样素材）

- A 厅伴奏：8 秒琶音 loop，**永远停在同一小节重新开始**；声源在 A 厅音箱位，随距离衰减；
- M05 工作声（瓷器、擦拭）与双击脚步：绑定实体位置，立体声声像；玩家与实体之间无视线时低通 + 衰减——**声音先于画面**；
- 低处声学：玩家进入 LOW_ZONE 时全局低通 + 音量微变（伴奏「变厚、变远」），不加滤镜不变色；
- 禁：音刺、水声、人声、儿童笑声、任何采样素材、任何「恐怖音效库」。

## 7. 任务回路与文本纪律

初始持婚宴录像带（HUD 一行）→ C 卡座 2.4 m 内按 `E` 归档 → CRT 亮 3 秒普通婚宴画面（纯色块）后回熄屏 → 返回 A → 落一行日志，**无结算、无评分、无解释**。玩家可见文本只有操作提示；以下命令输出必须为空：

```bash
rg -n "归面|仪式|记忆|海把|海补|认领|失踪" demo/web3d/src demo/web3d/index.html demo/web3d/main.js
```
