# 《返潮》项目总览与规划

> 一句话项目：**2001 年，中国北方一座海边小镇把送无尸亲人归海的「归面礼」做成了召回；潮来了，水没有来，水深来了。玩家是外乡来的警报线务员，用声音测出干燥空间里的深海，并决定哪些被记忆召回的人应当被再次送走。**
>
> 目标形态：与《死魂曲/SIREN》同量级的民俗恐怖游戏。单主角、章节制、约 6–10 小时；画质不低于优秀 PS3 后期作品（可量化定义见 [02 视觉文档](02_视觉原型设定.md)）。
> 技术栈为双栈裁决（详见 [06 技术文档](06_技术栈与制作工作流.md)）：**Demo 执行栈 = Three.js（浏览器，云端 Agent 可完整执行与验证）；正式产品栈 = Unreal Engine 5.8（本地开发机，迁移条件见 06 §1.4）。** 下一步 Demo 的逐步执行文档见 [docs/agent-playbook/](../agent-playbook/README.md)。

## 1. 项目现状总结（2026-08-24 审计）

### 1.1 真实成熟度

必须先说清一个事实：**这个项目目前的文档量与可玩物严重倒挂。** 交接包 292 个文件里有约 130 篇设定/评审/提示词 Markdown，而真正能运行的东西只有灰盒。

| 层 | 真实状态 | 证据 |
| --- | --- | --- |
| 世界设定 | 素材丰富但存在**三条互相竞争的基线**（见 1.2），无统一宪法 | 交接包 `01_核心设定/` 全部 |
| 玩法 | 只有行为层验证：状态机、航点、E/E/R 交互；没有任何一个核心机制做出过手感 | `MUD_FLAT_RUNTIME_VALIDATION`、H00 Round 4 日志 |
| 引擎工程 | UE 5.8 独立工程 `FanchaoH00UE` 可编译、可生成灰盒、状态机通过；**最后一次视觉 QA 黑屏，修复后未复验** | `00_整理索引/02_决策状态与时间线.md` |
| 美术 | 零正式资产。有 W01 婚宴厅 GLB、海洋馆走廊 GLB、若干 AI 目标帧（多数未通过审查）、M01 父亲多版本候选 GLB（明确不算正式资产） | `03_美术与候选资产/` |
| 声音 | 只有文档。声音是本作第一叙事层，却是目前最空的一层 | —— |
| 版本控制 | 原工作目录长期无 Git；本仓库刚建立 | 原始沟通记录 |

结论：项目处于**前期制作（pre-production）中段**。合理的说法是「已完成一轮昂贵但有价值的探索，尚未开始生产」。任何按「已有大量设定，快做内容」推进的计划都会失败。

### 1.2 文档债务：三条互相竞争的基线

交接包里并存三份都自称「当前」的核心：

1. **立项骨架（2026-08-04 评审稿）**：返乡录像员主角、四动词（读深度/干潜/改承压/记路线）、婚宴厅→海洋馆 Demo。用户评审意见是「这一稿不太行」，其中「北极星」类产品话术被明确否定，但四幕结构、海洋馆反证等局部仍有价值。
2. **基础设定第二轮稿（2026-08-04）**：归面礼、滩涂点火、无正面父亲、警报测深、外乡警报值守员。这是**用户逐句口述过因果、并明确下令执行**的一稿，民俗内核全部来自用户本人。
3. **H00-R0《婚宴后场：返席》（2026-08-04 重制决定）**：婚宴后场 60–90 秒行为切片，玩家归档录像带，实体沿旧后勤路线回返。空间/节拍/灰盒/状态机四个 Gate 已通过。

三者的主角、场景、核心动词各不相同。**本目录的裁决**（详细理由见 [05 审定文档](05_设定审定_保留与删除.md#0-三基线冲突的总裁决)）：

- 世界因果层采用**基线 2（归面礼）**——它是用户的原创民俗内核，也是本作区别于死魂曲/寂静岭的根。
- 物理层保留「潮来了但水没有来，水深来了」——三条基线共享，且已被用户多次确认。
- 主角统一为**外乡警报/广播线务员**，其职责天然覆盖警报塔、婚宴厅扩声、海洋馆广播与录像/广播室，从而把基线 2 的警报测深与基线 3 的 H00-R0 空间无损缝合（见 [01 故事文档 §3](01_故事背景设定.md#3-主角)）。
- H00-R0 保留为**行为验证资产**继续修复推进；垂直切片在其空间骨架上扩建，不推倒。

### 1.3 已有原型的价值

不要因为都是灰盒就轻视它们，也不要高估：

- **`FanchaoH00UE`（UE 5.8）**：当前主线。C++ 程序化灰盒、导演状态机、航点、归档交互、R 复位全部有日志证据。价值：垂直切片的行为地基。债务：视觉 QA 黑屏待复验。
- **`Mudflat_Runtime`（UE 5.8，冻结）**：证明了 UE 5.8 工程、输入、自动警报日志、GLB 资产导入可稳定运行。价值：纯技术证据与脚本复用，**不再作为创作基线**。
- **`h00_siren_ps3`（Three.js）**：11 项状态测试全过的交互骨架。价值：状态纯函数与测试方法论可抄；场景与叙事内容全部属于已否决的旧酒店方向，禁止回迁。
- **`f0_mobius_walk`（Three.js）**：莫比乌斯连续路线走通 124 秒、`route_parity` 翻转成立，但 30fps 独立宿主复核与外部盲测未过。价值：证明翻面在技术上可表达；也证明它**贵**——这是把莫比乌斯后置的直接依据。
- **W01 婚宴厅 GLB / 海洋馆走廊 GLB**：可复用的场景底料，需按新美术宪法重审材质。

### 1.4 最大风险（按杀伤力排序）

1. **AI 文档通胀复发**。交接包的病史清楚：探索稿互相替代、标题里的「核心/宪法」不代表优先级、生成图反向绑架设定。对策：本目录裁决权规则 + 每轮只准交付一个通过 Gate 的产物。
2. **PS3 级画质跳票**。目前没有一张实机画面达标。「PS3 级」对个人+AI 管线不是低目标，是高目标——它要求构图、材质、灯光的**导演能力**，而不是面数。对策：[02 视觉文档 §6](02_视觉原型设定.md#6-原型制作门) 的五图基准门先于一切资产生产。
3. **恐怖类型堆叠**。海洋+阈限+肢体+巨物+莫比乌斯全塞进一个 Demo 的冲动在历史文档里反复出现。对策：垂直切片只允许「民俗恐怖 × 干燥深海」一条主轴，其余全部锁进后期章节（见 [05 审定文档](05_设定审定_保留与删除.md)）。
4. **核心机制无手感风险**。警报测深至今只存在于纸面。如果「声学显深」在实机里读不出来，整个玩法塌方。对策：P1 阶段第一个 Gate 就是测深的可玩验证，早于任何美术投入。
5. **单人产能**。以个人+AI 工具链做 6–10 小时内容不现实。对策：垂直切片（8–12 分钟）作为对外找人/找钱的唯一敲门砖；在切片通过前不规划全篇内容量。

## 2. 阶段规划

原则：**每个阶段只回答一个问题；回答不了就不进下一阶段。** 不使用日历排期，使用通过门。

### P0 收束期（当前阶段）

**回答的问题**：项目是否有了唯一宪法与可运行的行为地基？

交付物：
1. 本目录七篇文档生效，交接包降级为历史材料；
2. H00-R0 行为地基有可重复运行的证据——已由 `demo/web/` 行为灰盒满足（浏览器可玩、截图可复现）；`FanchaoH00UE` 黑屏复验降级为本地开发机任务，不再阻塞 Demo 推进（裁决见 [06 §1](06_技术栈与制作工作流.md#1-技术栈裁决双栈)）；
3. 仓库版本控制制度落地（见 [06 技术文档 §5](06_技术栈与制作工作流.md#5-版本控制与目录制度)）。

通过门：新人只读本目录即可复述核心循环、形象库与当前禁令；H00-R0 行为切片可重复运行并截图。

不做清单：任何正式模型/贴图；任何新怪物设定；任何新地点文档。

### P1 垂直切片（Vertical Slice）

**回答的问题**：「警报测深 + 归来者 + 干燥深海」在 8–12 分钟里好不好玩、吓不吓人、像不像 PS3 级成品？

范围（在 H00-R0 空间骨架上扩建，节拍详见 [03 玩法文档 §5](03_核心玩法.md#5-垂直切片节拍8-12-分钟)）：

- 场景：婚宴后场闭环（A 宴会厅 / B 服务走廊 / C 录像·广播室 / D 卸货口 / E 洗涤间）+ 一段海洋馆服务走廊（翻面证明）；
- 机制：测深、读深度、改承压、仪式对策（不回头/不呼名）四项全部可玩；
- 威胁：M01「返席人（无正面的父亲）」正式资产 + 完整行为合同（形象见 [01 §4](01_故事背景设定.md#4-形象库看见即恐怖)）；
- 英雄资产：警报控制箱/线务工具包、宴会推车与餐具、承压门框/卷帘，三件近景可看；
- 声音：现实底层 + 测深回声 + 归来者声学感知，三层齐备。

内部 Gate 顺序（每个 Gate 失败退回，不得用堆资产补救）：

1. **机制门**：灰盒下测深→判读→改承压→绕开威胁的循环成立，陌生测试者两次测深内读懂深浅；
2. **气质门**：五张视觉基准图通过（[02 视觉文档 §6](02_视觉原型设定.md#6-原型制作门)）；
3. **威胁门**：M01 低模行为四测试通过（预测回返、三视人物重心、路线因果、720p 轮廓双读）；
4. **资产门**：英雄资产近景不再读成灰盒；
5. **成片门**：无解释文字的完整 8–12 分钟录像，外部盲测能复述「这里是干的，但已经在海底」与「它是被记错的人」。

不做清单：莫比乌斯全镇；多角色；战斗系统；背包/资源管理；网吧/门诊等章节场景；结局内容。

### P2 Alpha（第一小时）

**回答的问题**：核心循环能否支撑一小时不重复的体验，并完成从日常到点火事件的叙事起飞？

范围：
- 完整第一小时（节拍见 [03 玩法文档 §4](03_核心玩法.md#4-第一小时体验节拍)）：抵达小镇 → 三张工单的日常 → 滩涂集体送面 → 点火事件 → 第一次真正的归来者遭遇 → 回到婚宴后场（即垂直切片内容的叙事就位）；
- 场景新增：新市场停靠点（简化）、滩涂与警报塔、一段家属区街巷；
- 系统：磁带/记录经济第一版（见 [04 机制文档 §5](04_核心机制.md#5-记录经济记录即喂养)）、称呼/认领的叙事状态机第一版；
- 声音：全部公共广播链（警报塔—扩音器—室内喇叭）可寻址。

通过门：外部测试者一小时留存；能复述至少两个形象的「看见什么」并在游玩中出现自发回避行为（绕开背影、拒绝回头）；死亡/失败后自愿重来。

不做清单：莫比乌斯翻面实装（只允许一次「回到同一地点但称呼已变」的软翻面）；第二个英雄怪物之外的新威胁；多结局。

### P3 内容扩充（Beta 向）

**回答的问题**：世界能否长成全镇，而不稀释主轴？

范围（按优先级，允许砍尾）：
1. 海洋馆完整章节（「缸内海水正常、缸外干燥承压」的全作反证场景）；
2. 家属区/旧村章节（认领与称呼系统的主战场；「饭已经做好了」愿望空间事件）；
3. 莫比乌斯路线首次实装（R1 环湾海堤，一圈翻面、两圈复原；使用 F0 已验证的公理层，见 [05 审定文档](05_设定审定_保留与删除.md#33-莫比乌斯小镇改造后置)）；
4. 后续威胁登场（M02 迎宾的人 / M03 洗涤间的搁浅者 / M04 敬酒的女人，形象已锁定于 [01 §4 形象库](01_故事背景设定.md#4-形象库看见即恐怖)）；
5. 三结局实装（[01 故事文档 §6](01_故事背景设定.md#6-剧情骨架每行一幕不再展开)）。

通过门：每个新章节承担一种新的社会功能与一条新规则，删掉它全作有损失；任何章节不得只是换皮关卡。

## 3. 本规划的三个纪律

1. **少而硬**。一个测深机制做到极致，胜过十个半成品系统。所有「有意思但不在主轴上」的想法进 [05 审定文档](05_设定审定_保留与删除.md) 的降级区排队，不进生产。
2. **声音先行**。本作的恐怖预算大头在声音而不是贴图。每个异常事件的验收顺序永远是：声音成立 → 动作成立 → 画面成立。
3. **证据文化**。「已完成」只承认三种证据：可运行、有截图/录像、有日志。文档写完不算完成任何事——包括本文档。
