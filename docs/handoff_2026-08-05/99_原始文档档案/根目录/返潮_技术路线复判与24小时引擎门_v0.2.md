# 《返潮》技术路线复判与 24 小时引擎门 v0.2

> 复判结论：首周可玩 Demo 不再以 UE5 为主。采用 **Godot 4 + Blender + 照片贴图低模／预渲染背景／局部实时 3D 的混合 2.5D**。目标不是降低美术强度，而是把高配主机用于生产高质量画面，把玩家电脑从昂贵的全实时渲染中解放出来。

> 2026-07-15 技术门结果：Blender glTF Blend Shapes、Godot Compatibility、远程截图和 Windows EXE 导出均已通过，继续采用本路线。墙体灰盒的圆形鼓包与单网格迁移脊未达到美术要求，下一版改为基墙、修补薄壳、内部压力和响应物件的分层资产；详细见《返潮_墙体24小时技术门结果_v0.1》。

## 1. 为什么高配开发机不能消除 UE5 风险

SSH 高配主机只能改善：

- 编辑器是否流畅；
- Shader、资产导入与打包速度；
- Blender 离线渲染速度；
- 是否能制作高质量演示片。

它不能改善朋友电脑的 GPU、显存、内存和驱动，也不能自动减少：

- UE5 工程初始化、资产组织和每次打包的等待；
- Lumen、体积雾、透明材质、动态阴影和高分辨率贴图的运行成本；
- 为低、中、高画质分别调试的工作；
- 玩家首次运行时的 Shader、驱动与兼容问题；
- “既然用了 UE5，就应该处处达到高保真”的无形制作压力。

Epic 当前给出的 UE5 推荐开发配置是 32 GB 内存和 8 GB 以上显存；Lumen、Nanite 等招牌功能另有较新的 GPU 与 DX12／SM6 要求。UE5 确实具有完整的伸缩设置，但官方同样强调：支持更宽的硬件范围会增加内容决策、优化与测试成本。对于一周个人 Demo，这部分成本过大。

## 2. 重新定义我们真正需要的“画质”

《返潮》不需要同时满足：开放世界、自由摄影、全动态 GI、海量高模、复杂物理与电影级数字人。它真正需要的是：

1. 千禧海边城镇像真实存在过；
2. 人脸、材料和普通生活具有照片可信度；
3. 一个异常在运动、声音和因果上足够独特；
4. 关键镜头的构图具有攻击性；
5. 普通电脑能够稳定看到我们精心控制的结果。

这些目标更适合“高质量离线生产 + 轻量实时交互”，而不是所有像素都由玩家显卡实时计算。

## 3. 路线比较

| 路线 | 首周完成度 | 低配覆盖 | 写实上限 | 动态异常 | 主要风险 | 本次结论 |
|---|---:|---:|---:|---:|---|---|
| UE5 全实时 | 低 | 低—中 | 很高 | 很强 | 工程、材质、Shader、打包与优化吞掉首周 | 暂缓 |
| Unity 6 URP | 中 | 中—高 | 中—高 | 强 | 编辑器与资产管线仍较重；想做体积效果仍需定制 | 第一备用 |
| Godot 4 Forward+ 全实时 | 高 | 中 | 中 | 强 | 高级雾仍要求较新 GPU；默认写实感不足 | 不单独采用 |
| Godot 4 Compatibility 全实时 | 很高 | 高 | 低—中 | 中 | 缺少体积雾、屏幕空间反射等高级效果 | 作为低配运行层 |
| Godot + Blender 混合 2.5D | 高 | 高 | 高（受离线渲染保障） | 中—强 | 摄像机和前后景遮挡需预先设计 | **首选** |
| Three.js 全实时 | 中 | 中—高 | 中 | 中 | 很多引擎功能需要自行搭建，浏览器差异增加 QA | 不作为主版 |

## 4. 最终选择：不是“像素风”，而是照片现实的混合 2.5D

### 运行层：Godot 4

Godot 负责：

- 行走、热点交互、路线和状态；
- NPC 与低模角色；
- 音频空间、字幕、档案和 RPG 数据；
- 近景门、墙、玻璃、纸张等可交互网格；
- 实时形变、粒子、灯光变化和危机事件；
- Windows 原生包；之后可尝试 Web 传播版。

默认首先以 **Compatibility renderer** 建立低配版本。它使用较广泛的 OpenGL 路径，Godot 官方将其定位为低端桌面、移动和 Web 的兼容选择。高画质版本可以切到 Forward+，但不能让玩法依赖只有 Forward+ 才存在的效果。

### 生产层：Blender

高配 SSH 主机主要用于：

- 搭建海洋馆完整几何；
- 渲染固定／半固定机位的高质量背景；
- 烘焙光照、阴影、反射与环境雾；
- 制作墙体和玻璃的 Shape Keys；
- 输出照片贴图低模、法线、AO 与事件动画序列；
- 必要时把最昂贵的异变渲染成与实时画面无缝衔接的短序列。

Godot 官方推荐 glTF 2.0 作为 3D 资产格式，并支持 Blender 场景、动画和 Blend Shapes 的导入，适合这个管线。

### 画面构成

一个镜头由四层组成：

1. **预渲染远景**：建筑主体、复杂灯光、海雾和反射；
2. **简化 3D 空间**：碰撞、门、地面、遮挡和玩家移动；
3. **实时近景异常**：墙体形变、玻璃弯曲、雾的压力前缘和物件响应；
4. **照片现实角色**：照片贴图低模或有深度信息的 2.5D 人物，保留略微不顺滑的真实表演感。

这接近老式生存恐怖的预渲染思路，但不使用纯静止背景：关键近景仍然是真实网格，雾、灯光和人物能够穿过前后景，镜头可进行有限位移。

## 5. 摄像机必须相应改变

不再以完全自由的现代第三人称镜头作为首周要求。采用：

- 房间级固定机位；
- 进入关键区域后的缓慢轨道／有限旋转；
- 玩家靠近互动点时自然切到近景；
- 个别狭窄空间使用肩后镜头；
- 切镜遵守人物位置和方向连续性，不故意用摄像机制造操作困难。

固定构图不是单纯为了省性能。它能确保墙体远端鼓起、门框被挤压、玻璃反射弯曲等证据同时进入画面，使冲击力不再依赖玩家偶然站对位置。

正式 RPG 仍可在地点间自由探索；这里限制的是房间内的摄影范围，而不是把游戏变成点击式幻灯片。

## 6. 三种效果如何降本但不降强度

### 墙内积液转移

- 墙、门框和柜子保留为实时低模；
- 4–6 个 Blend Shapes 控制积液在不同位置之间转移；
- 背景墙面拥有预烘焙的光影，形变层只覆盖受影响区域；
- 湿度和起皱用轻量 Shader；
- 排水高潮可以由实时形变衔接一段短离线动画，再回到可行走的旧房间。

这样仍然保留玩家按压与远端反应，不需要真实流体、全场动态 GI 或建筑破坏。

### 不存在的深海压力

- 平直玻璃、框架、固定件和外部巴士参照保留实时；
- 玻璃弯曲用 Blend Shape，折射只在高画质版启用；
- 低画质版通过反射贴图 UV 偏移、框架位移和巴士直线变形证明压力；
- 纸张、吊牌、NPC 受力使用预设动画，不运行全场物理；
- 两扇门的相反压力仍由游戏状态控制。

效果的核心是前后证据链，不是昂贵的透明材质。

### 海雾

Godot 的真实体积雾只在 Forward+ 可用，Compatibility 和 Web 不能使用。首周因此采用三层替代：

- 背景中的大尺度海雾直接离线渲染；
- 中景使用深度雾和少量低分辨率雾片；
- 门口压力前缘使用一张有厚度的半透明网格、粒子碎边和同时发生的物件动画。

Godot 官方也明确列出用 QuadMeshes 模拟局部体积雾的方案，其优势是兼容所有渲染器且通常成本更低。我们不把这种替代当技术妥协，而把雾的平整前缘设计成《返潮》自己的视觉特征。

## 7. 对玩家硬件的暂定目标

在看到朋友配置前，采用以下保守目标，而不是把开发机当最低配置：

- Windows 10／11 64 位；
- 8 GB 内存；
- 具有 OpenGL 3.3 或 DX11 能力的集成显卡／老独显；
- 低画质 720p 或 900p，稳定 30 FPS；
- 中画质 1080p，稳定 30 FPS；
- 原生 Windows 包优先，浏览器版属于额外传播渠道；
- 首周包体预算暂定不超过 1.5 GB，最终以预渲染序列压缩测试决定。

这些是项目预算，不是已经验证的承诺。拿到 SSH 与至少一台朋友的低配机后必须实测。

## 8. 24 小时引擎门

这不是先做完整 Demo，而是制作一个可删除的小型技术原型，只回答：“这条管线能否用低成本表现《返潮》的招牌异常？”

### 测试场景

只做一个房间、一面墙、一扇门和一个固定机位：

- Blender 输出背景、墙体 glTF 和 4 个 Blend Shapes；
- Godot 中实现点击／按压近处，远处鼓起并挤窄门缝；
- 加入一个照片材质、一个贝壳落盆声音和两层假雾；
- 导出 Windows 版本；
- 高配、中配、至少一台低配机分别运行。

### 通过条件

- 不看说明也能读懂“体积从这里转移到了那里”；
- 背景与实时墙体衔接不产生明显贴纸感；
- Compatibility 低画质仍保留异常证据；
- 低配目标机器能够稳定游玩；
- 从修改 Blender 资产到得到新构建的迭代过程足够短；
- 打包后的程序能被普通朋友直接启动。

### 失败后的唯一后备

如果失败原因是 Godot 的渲染／动画管线而非资产设计，立即切换 **Unity 6 URP**，复用同一批 Blender、glTF、贴图、音频和事件逻辑。不上 UE5，也不同时维护两个正式版本。

如果失败原因只是画面本身没有恐怖强度，则不换引擎，回到动作和构图设计。引擎不能替创意背锅。

## 9. 一周计划相应调整

### 第 0–1 天：技术门

完成上面的最小房间并在至少一台低配机导出测试。当天决定继续 Godot 或切 Unity URP。

### 第 2 天：海洋馆三机位与正常状态

完成大厅、员工走廊、出口三个主要机位和简化碰撞；建立危机前灯光与正常海雾。

### 第 3 天：完整墙体事件

完成多点积液转移、柜子／门框响应、声音和旧房间释放。

### 第 4 天：玻璃压力事件

完成平直基准、反射参照、固定件序列、两扇门的相反压力。

### 第 5 天：危机开始与声音

完成“巨大吸气”、雾的压力前缘、广播声源错位和全局状态切换。

### 第 6 天：NPC 与照片现实

加入一个员工或游客，完成克制反应、照片贴图和有限动作；不做完整对白树。

### 第 7 天：低配打包与公开素材

同时产出：

- 普通电脑能运行的 Windows Demo；
- 高配画质下录制的无剪辑实际游玩片段；
- 少量危机前后对照图；
- 设定集中的技术与视觉说明。

## 10. UE5 的新位置

UE5 不被否定，它被移到合适的位置：

- 未来在玩法与美术方向成立后制作高保真重制；
- 用于关键怪物、场景或宣传镜头的视觉研发；
- 当项目团队、时间和目标硬件提高后再评估；
- 不再承担“第一周同时证明玩法、视觉、性能和发布”的全部风险。

首周的震撼应该来自一个低配电脑也能完整经历的强事件，而不是只有开发机能运行的一段技术展示。

## 11. 配置到手后要立即确认的信息

SSH 主机：

- 操作系统及版本；
- GPU 型号、显存和驱动；
- CPU、内存、可用硬盘；
- 是否能进行图形会话／远程桌面，还是只有终端；
- 是否允许安装 Blender、Godot、导出模板、ffmpeg 与系统依赖；
- 目标 Windows 构建是否需要从 Linux 交叉导出。

朋友测试机至少收集三项：Windows 版本、显卡型号、内存。最好选择最差的一台作为真正下限，而不是用平均配置推测。

## 12. 当前技术依据

- Godot 的 [系统要求](https://docs.godotengine.org/en/stable/about/system_requirements.html) 将简单原生项目的基线列到 2 GB RAM，并强调最终要求取决于项目内容且必须在低端硬件实测；
- [渲染器比较](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html) 将 Compatibility 定位为旧／低端桌面和 Web，Forward+ 提供完整高级 3D 功能；
- [体积雾文档](https://docs.godotengine.org/en/stable/tutorials/3d/volumetric_fog.html) 明确体积雾仅支持 Forward+，同时建议用 QuadMeshes 制作更低成本、跨渲染器的替代效果；
- [3D 场景导入](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/index.html) 与 [功能列表](https://docs.godotengine.org/en/stable/about/list_of_features.html) 支持 Blender／glTF 资产工作流；
- [项目导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html) 支持从命令行直接导出 Windows、Linux 和 Web 构建；
- Epic 的 [UE5 硬件规格](https://dev.epicgames.com/documentation/unreal-engine/hardware-and-software-specifications-for-unreal-engine) 与 [可伸缩性说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-and-the-developer-for-unreal-engine) 是本次暂缓 UE5 的主要依据。
