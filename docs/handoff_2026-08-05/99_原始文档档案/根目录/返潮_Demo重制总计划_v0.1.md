# 《返潮》Demo 重制总计划 v0.1

日期：2026-08-04  
状态：重制规划，尚未进入正式资产生产  
目标：先做出一段空间、人物行为、异常规则彼此成立的 PS3 级恐怖垂直切片，再扩展到全镇、海洋馆和完整怪物谱系。

## 0. 本轮重置决定

当前泥滩/警报塔版本冻结为失败原型与技术证据，不继续在其上叠加角色、贴图或特效。保留文件，不删除、不覆盖；后续只提取其中可复用的输入、重置、日志和打包脚本。

重制不是推翻《返潮》的核心，而是重新排列制作顺序：

> **先锁定体验合同 → 画俯视地图 → 用占位体验证行为 → 搭正常场景 → 验证异常因果 → 最后生成正式模型与贴图。**

本轮不允许“先生成一张很酷的怪物图，再反向发明地图和玩法”。

## 1. 设定层级

### CANON：本轮继续有效

- 时间与现实底片：2001 年前后的中国沿海小镇，千禧媒介、公共单位、婚宴、广播、录像、登记和熟人社会。
- 核心异常：**潮来了，但水没有来，水深来了。**干燥空间承受深海压力、沉积、声音和时间的后果。
- 气质：普通生活先成立；人物可以温和、尴尬、好笑、体面，恐怖再从礼数、称呼、位置和重复动作中进入。
- 世界骨架：小镇可以具有莫比乌斯式的路线/关系回返，但第一 Demo 只证明一个局部回路，不展示全镇百科。
- 主题方向：保存一个人、替一个人维持原位置，可能正是禁止他改变和离开的方式。
- 视觉异常：优先表现为材料受力、身体动作、声音来源和空间对应关系失效，不使用水下滤镜来代替设计。

### CANDIDATE：只有通过 Gate 后才能升格

- 石化海洋生物复眼：保留为实体的候选视觉语言，不提前决定完整外形、名称或谱系。
- “背影是具体的人，正面是海床替记忆补上的错误结构”：保留为 M01 的角色命题。
- 婚宴后场作为第一 Demo 的现实底片：优先候选，因为它同时提供公共礼数、缺席、录像和座位/身份关系。
- 海洋馆服务区作为第二个验证场景：用于证明“有正常海水的容器，外部干燥走廊反而承受深海后果”，不与第一 Demo 同时塞入。

### ARCHIVE：本轮不再作为约束

- 外星异形、酒店发育器官、灭世生物生态、尸兔、触手/珊瑚/器官填空。
- 纯泥滩、警报塔、悬锤/钥匙等没有明确空间因果的视觉符号。
- 先做怪物图鉴、统一敌人谱系、资源门、战斗数值和全镇终局。
- 用蓝光、雾、水线、湿地脏纹理或“海洋装饰”直接告诉玩家这里发生了异常。

## 2. 第一 Demo 的体验合同

### 暂定标题

**H00-R0《婚宴后场：返席》**

这不是最终章节名，而是一个用于压力测试的单地点垂直切片。

### 玩家在 90 秒内应经历什么

1. 玩家进入仍在收拾的千禧婚宴场所，能看出这里正在完成什么工作。
2. 玩家接到一个普通任务：把一盘录像带/登记物送回后场的录像或广播房间。
3. 玩家经过公共宴会厅与服务走廊，发现同一段生活声音在不该存在的位置继续完成。
4. 玩家根据门框、地面、家具和声音的共同变化，判断一条“浅处路线”和一条“深处路线”。
5. 玩家返回时，一个原本属于现实底片的人沿旧工作路线回到原位置；它不解释、不吼叫、不像普通追击敌人。
6. 玩家选择是否让它回到那个位置。选择改变的是空间关系和人物身份，不是 RPG 数值。

### 三个必须先成立的读法

- **现实读法**：这是具体的 2001 年海边小镇婚宴后场，不是“恐怖游戏房间”。
- **异常读法**：这里没有进水，但某一段空间已经承受过不属于陆地的深度。
- **威胁读法**：实体不是一张怪脸；它是一个被旧位置、旧工作和旧称呼重新固定的人。

若 5 秒静帧内读不出第一条，若 30 秒内读不出第二条，若实体无法从普通人物行为连续变形而来，立即退回前一 Gate。

## 3. 场景与地图设计

### 3.1 地图不是背景图，而是规则的证明器

先做俯视图，再做 3D。地图必须让“人物为什么从这里出现、为什么只能沿这条路线回来、玩家为什么要冒险走低处”一眼可解释。

初始地图采用一个小型闭环，不做开放镇：

```text
             ┌──────────────┐
             │ A 宴会厅      │
             │ 公共现实底片  │
             └───┬──────────┘
                 │ 正常服务口
         ┌───────┴────────┐
         │ B 后场服务走廊  │──────┐
         │ 浅/深路线分叉    │      │
         └───────┬────────┘      │
                 │               │
         ┌───────┴────────┐      │
         │ C 录像/广播房   │──────┘
         │ 证据与身份      │
         └───────┬────────┘
                 │ 只能从旧工作路线返回
             ┌───┴──────────┐
             │ D 侧门/卸货口  │
             │ 硬质压力证据  │
             └──────────────┘
```

第一版只需要四个空间节点、一个公共入口、一个服务回路、一个可观察的低处和一个回返点。任何不能改变路线判断的房间先不建。

### 3.2 空间 Gate

- 墙、门、桌、灯、录像机和服务台有明确用途、尺度和连接关系。
- 玩家不用 UI 也能知道“我从哪里来、还可以往哪里走、为什么这条路更危险”。
- 异常不沿瓷砖腰线、墙缝或装饰边界生成；它由多个不同物体在同一高度/同一声学关系下共同证明。
- 每个镜头只承担一个主读点：现实功能、异常材料、人物动作或路线威胁，不能全部堆在一帧里。
- 地图的闭环要服务于“返回同一个位置但它已经不再是同一个位置”，不是为了迷路。

## 4. NPC 与怪物设计顺序

### 4.1 普通人物先于实体

先做一名可记住的普通工作人员/亲属：

- 公共位置：他负责什么，为什么别人认识他；
- 日常节奏：一个过度认真的工作动作或客气习惯；
- 私人愿望：希望保住谁、送走谁、证明什么；
- 错误的正常：返潮后仍坚持哪项工作流程。

最低动作集：站立、拿物、递交、停顿、回头、沿工作路线离开、在旧位置重新出现。

### 4.2 实体不是“怪物外形”，而是行为规则

M01 暂称“返席人”，仅作为设计名，不是最终名称。

- 轮廓：背面仍是具体的 2001 年沿海劳动者/父亲，服装、肩线、鞋和工作疲劳必须可信。
- 正面：脸部身份被一整块干燥、沉重、石化的海洋生物复眼甲壳取代；它不是昆虫头、外星脸、触手或血肉器官。
- 身体逻辑：复眼不是贴纸，而是身体前侧承担了“识别/观察/归档”功能后的结构替换；接缝、重量、重心和动作要服从这一点。
- 移动逻辑：它不随机巡逻。它沿一条旧工作路线回到一个旧位置；当玩家改变物件、声音或门的状态，路线的可达性发生变化。
- 恐怖逻辑：最先看到的是背影和熟悉的工作姿势；正面只在玩家必须判断路线时出现。
- 反例：不可用突然跳出、随机追逐、正面怪脸、过度爬行、倒放动作、无因由瞬移来制造恐怖。

### 4.3 怪物 Gate

在正式生成角色前，必须用胶囊体/低模占位体通过：

1. 10 秒移动测试：玩家能预测它要回哪里，但不知道它何时完成回返。
2. 3 个站位测试：背面、侧面、正面都保留同一个人物重心和工作行为。
3. 路线因果测试：删除材质和声音后，仍能看出它为什么走这条路。
4. 视觉测试：720p 下先读出“人/工作服/方向”，再读出“石化复眼错误结构”。

## 5. 视觉生产规范

### 5.1 PS3 级不是堆面数

首个切片的目标是 720p、稳定镜头、可控灯光、可读轮廓和密集但有用途的材质细节。优先级是：

1. 构图和空间关系；
2. 人物/道具的真实尺度；
3. 正常材质与压力后果；
4. 角色 silhouette 和动作；
5. 光色层次；
6. 近景贴图和微细节；
7. 最后才是额外特效。

色彩基准：冷灰建筑、褪青绿公共设施、暖骨/旧纸色记忆物、旧蓝工服、单一事件红。色彩不能用一层蓝灰后期把逻辑抹平。

### 5.2 每次生成只问一个问题

每一轮只交付一项：

- 现实底片目标帧；
- 俯视地图/路线图；
- 普通 NPC 三视图；
- 实体三视图；
- 10 秒移动行为；
- 正常/受压材质对照；
- Unreal 720p 运行帧。

每项必须附：问题、输入约束、禁止项、模型/工具、版本、结果、是否通过、退回原因。

## 6. Gemini、网页 ChatGPT 与本地工具的分工

### Codex：总监、集成与验收

- 读取设定和工程事实，维护 CANON/CANDIDATE/ARCHIVE；
- 把用户判断翻译成 brief、地图、行为表和 Gate；
- 调用 Gemini/网页 ChatGPT，但不把任何一次生成结果自动升格为正式资产；
- 管理文件、许可证、来源、导入清单、构建和运行时回归；
- 只有通过 Gate 的 GLB/贴图/动画才能进入 Unreal 主线。

### 网页 ChatGPT：视觉总监与审稿人

目标窗口：用户登录的网页 ChatGPT 端，名称沿用“反潮视觉资产生成”。

- 审查设定是否有趣、空间是否可读、怪物动作是否有因果；
- 设计短提示词、负面提示词、构图和 A/B 评审表；
- 用同一 brief 比较 2–4 个视觉方案；
- 只输出建议、图像或审计结果，不直接修改本地工程。

浏览器接管必须先通过“已登录目标页 + 当前会话可控”诊断；没有桥接时不假装完成网页审计，也不把聊天窗口截图当作本地资产。

### Gemini / Antigravity CLI：执行代理

命令入口已经存在：`C:\Users\ACE\AppData\Local\agy\bin\agy.exe`，当前可用版本为 1.1.10。

- 根据已批准 brief 写 Blender Python、批量生成低模、导出 GLB、建立 manifest；
- 运行本地脚本、检查命名/面数/材质槽/坐标/骨架；
- 对文本设定和 JSON 结果做第二意见；
- 只有在它能稳定读取或回传图像证据时，才把它列为视觉审图者。当前直接让 CLI 检查 PNG 曾出现执行终止，因此不能虚报“Gemini 已完成视觉审计”。

标准调用形式：

```powershell
agy.exe -p "<严格限定输入、输出格式和禁止修改范围的任务>" --model gemini-3.1-pro-high --print-timeout 2m
```

## 8. A/B 测试：Gemini 与网页 ChatGPT

不比较“谁更聪明”，只比较它们在各自职责上的有效性。用同一份 brief、同一套禁止项和同一时间预算：

| 测试 | 网页 ChatGPT | Gemini / Antigravity | 评分 |
| --- | --- | --- | --- |
| 设定压缩 | 10 分钟产出一句异常和三条可玩后果 | 10 分钟产出同格式结果 | 约束遵守、可玩性、时代准确度 |
| 视觉提示 | 20 分钟给出 2–4 个构图方案 | 20 分钟转成可执行 Blender/生成任务 | 单一读点、负面约束、可执行度 |
| 空间灰盒 | 提供审查意见 | 45 分钟生成/修改俯视图和低模 | 尺度、路线、可复现性 |
| 资产实现 | 审三视图/截图 | 60 分钟导出 GLB、manifest 和技术检查 | 轮廓、因果、技术合格率 |

评分低于 4/5 的方案不进入下一轮。Gemini 不能通过本地文件写入来替代 ChatGPT 的视觉审查；ChatGPT 不能通过漂亮概念图替代 Unreal 运行证据。

## 9. Gate 与执行轮次

### Round 0：重置与事实表

产物：本文件、现有资产清单、失败样本清单、版本控制入口。  
通过：所有内容标记 CANON/CANDIDATE/ARCHIVE，泥滩原型冻结。

### Round 1：场景三选一纸面测试

候选：婚宴后场、食堂侧间、海洋馆服务走廊。三者都只画俯视图和火柴人，不建资产。  
通过：选出一个现实功能最清楚、能形成闭环、能承载单一异常的场景。默认优先婚宴后场，但以测试结果为准。

### Round 2：地图与节拍

产物：俯视地图、玩家路线、NPC 旧工作路线、实体出现条件、声音来源表、90 秒 beat sheet。  
通过：删除怪物后，路线仍有目标；删除声音后，空间仍有用途；删除文字后，异常仍可复述。

### Round 3：正常态灰盒

产物：Unreal 或 Blender 的无贴图空间、普通灯光、固定镜头、占位人物。  
通过：测试者在 5 秒内说出地点功能、入口、出口、主要工作对象；不得有漂浮、穿插、比例错乱或无来源的焦点物。

### Round 4：异常行为原型

产物：压力高度/路线/声学状态的可玩占位；不使用正式怪物模型。  
通过：玩家能预测规律，却不能完全控制结果；一次普通操作能改变路线判断，而不是只触发过场。

### Round 5：普通 NPC

产物：普通人物低模、服装色块、递交/停顿/回头/回返动作。  
通过：人物先像真实工作人员，再像《返潮》人物；动作不靠夸张恐怖表演。

### Round 6：实体低模与三视图

产物：M01 低模、正侧背三视图、10 秒动作、行为 manifest。  
通过：背影是人，正面是错误结构；石化复眼服从身体受力和重心；不产生昆虫/外星/普通海怪读法。

### Round 7：正式资产与贴图

产物：通过 Gate 的 GLB、贴图、材质实例、LOD/碰撞、来源和许可证。  
通过：模型只在已确定的镜头和动作中服务，不让贴图新增未经批准的叙事。

### Round 8：Unreal 垂直切片

产物：60–90 秒可重置 Demo、720p 固定镜头、运行日志、三张审片帧和一段行为录像。  
通过：空间、人物、实体、声音和路线共同成立；失败时可定位到具体 Gate，而不是继续堆资产。

## 10. 立即执行顺序

接下来只做这四件事：

1. 为婚宴后场、食堂、海洋馆服务区各画一张纸面俯视地图，不生成图片，不导入模型。
2. 用五项标准打分：现实功能、路线闭环、异常可证明性、人物关系、现有资产复用。
3. 选出第一 Demo 场景后，写一页 beat sheet 和一张声音/路线因果表。
4. 用占位体在本地跑通第一条 60–90 秒路线，再开始任何正式怪物或贴图工作。

## 11. 完成定义

本轮 Demo 不是“有一张漂亮图”，而是同时满足：

- 观看者先认出一个具体的千禧沿海公共场所；
- 观看者能说出唯一异常及其材料/声音后果；
- 玩家知道下一步为何要走某条路线；
- NPC 的普通工作行为在实体行为里仍可辨认；
- 石化复眼是身体逻辑的结果，不是装饰贴片；
- 90 秒内有一次可操作判断、一次空间回返和一次不可逆的关系变化；
- Unreal 可以启动、重置、录制，720p 画面没有漂浮物、尺度错误和未解释的构图焦点；
- 所有正式资产都有来源、许可证、生成提示、Gate 记录和可回退版本。

只有这套最小闭环通过，才进入海洋馆翻面、莫比乌斯小镇、多视角叙事和更完整的怪物设计。
